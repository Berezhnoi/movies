# Movies API — Project Specification

## Overview

A Go REST API for a movie catalog, backed by PostgreSQL, with a server-rendered HTMX web UI in the same
binary. It provides JWT authentication, role-based access control (RBAC), SQL migrations, generated Swagger
documentation, and in-memory contract tests.

## Tech stack

| Concern | Choice |
|---|---|
| Language | Go 1.21 (`go.mod`, module `homework`); CI runs Go 1.22 |
| HTTP | Gin |
| Persistence | PostgreSQL via GORM; schema managed by golang-migrate SQL files in `migrations/` |
| Auth | HS256 JWT (`internal/auth/jwt.go`), bcrypt password hashes (`internal/auth/password.go`) |
| Web UI | `html/template` + HTMX 2.0.4 (vendored), embedded with `go:embed` |
| API docs | Swagger 2 generated by swag v1.16.4 into `docs/` |
| Optional integration | Signed `user.created` webhook to a Go Lambda (`functions/notifier`) on Floci |

## Architecture

```
cmd/api/              server entry point: config, GORM, JWT manager, webhook, graceful shutdown
cmd/seed/             creates the first admin from ADMIN_EMAIL / ADMIN_PASSWORD
internal/app/         router wiring (NewRouter, NewRouterWithDeps) and the contract test suite
internal/handler/     JSON API handlers; routes.go registers routes on RBAC groups
internal/handler/web/ web UI handlers, renderer, CSRF and cookie-auth middleware
internal/middleware/  API middleware: CORS, recovery, logging, body limit, Bearer auth, RequireRole
internal/service/     business rules, validation, pagination, typed errors
internal/repository/  repository interfaces with in-memory and GORM implementations, catalog search
internal/apperr/      maps service errors to HTTP status + JSON error body
internal/auth/        JWT issue/parse, password hashing
internal/config/      environment configuration
internal/model/       API types and GORM entities
internal/webhook/     user-created webhook client and UserRepository decorator
web/                  embedded templates and static assets
migrations/           numbered up/down SQL migrations
functions/notifier/   Lambda (separate Go module)
infra/                VM, Terraform, Floci and K3s lab deployment
tools/                verify-isolation.sh
scripts/              grading scripts (official, do not edit)
docs/                 generated Swagger files and lab notes
```

Request flow: `handler` → `service` → `repository`. Handlers return service errors through
`apperr.WriteError`, which produces `{"code": ..., "message": ...}` with the matching status.

### Two router modes

`internal/app/app.go` builds the router in two modes:

- **`app.NewRouter()`** is used by the contract tests. It uses in-memory repositories. All API routes are
  registered **without** authentication. There is no web UI and no Swagger.
- **`app.NewRouterWithDeps(deps)`** is used by `cmd/api`. It always runs in secure mode: public,
  authenticated, editor/admin and admin route groups, plus Swagger. It mounts the web UI when
  `WEB_UI_ENABLED=true`.

## Roles

Roles are `viewer`, `editor`, and `admin`. The database enforces them with a `CHECK` constraint, and
`model.IsValidRole` validates them in code. Public registration always creates a `viewer`. The first
admin is created with `make seed-admin`.

| Capability | viewer | editor | admin |
|---|:-:|:-:|:-:|
| Read movies | ✓ | ✓ | ✓ |
| Create / replace movies | | ✓ | ✓ |
| Delete movies | | | ✓ |
| List users, change roles | | | ✓ |
| Create accounts in the web UI | | | ✓ |

## JSON API (`/api/v1`)

Authentication uses the `Authorization: Bearer <token>` header only. The API never reads the browser
cookie.

| Method | Path | Access |
|---|---|---|
| `POST` | `/auth/register` | Public (creates a `viewer`) |
| `POST` | `/auth/login` | Public; returns an access token |
| `GET` | `/movies` | Public; `page`, `limit` (default 10, capped at 100), `genre` |
| `GET` | `/movies/{id}` | Public |
| `GET` | `/me` | Authenticated |
| `POST` | `/movies` | Editor or admin |
| `PUT` | `/movies/{id}` | Editor or admin (full replace) |
| `DELETE` | `/movies/{id}` | Admin |
| `GET` | `/users` | Admin; `page`, `limit` |
| `PUT` | `/users/{id}/role` | Admin |

`GET /health` (also `/api/v1/health` when Swagger is enabled) reports liveness. Swagger UI is served at
`/swagger/index.html`. Unknown routes return `404 not_found`. Wrong methods return `405`.

A movie has `id`, `title`, `director`, `country`, `genre`, `release_year` (nullable), `synopsis`
(nullable), `created_at`, and `updated_at`. In PostgreSQL, genres and directors are normalized into their
own tables (migration `000002`). `internal/repository/movie_mapping.go` maps them to the flat API shape.

## Web UI

| Route | Access |
|---|---|
| `GET /`, `GET /catalog` | Catalog; anonymous users are redirected to login |
| `GET /web/movies` | HTMX live-search rows; login required |
| `GET, POST /login`, `POST /logout` | Public login; logout requires a session |
| `GET, POST /movies/new`, `GET, POST /movies/{id}/edit` | Editor or admin |
| `DELETE /web/movies/{id}` | Admin; returns an empty 200 so HTMX removes the row |
| `GET, POST /register` | Admin only (creates accounts; triggers the webhook if configured) |
| `GET /static/{path}` | Public embedded assets |

Search, pagination, and forms also work without JavaScript. After a live search the pager is hidden until
Enter reloads the page, because its links refer to the previous result set.

## Security

- **Browser session:** after login, the JWT is stored in the `access_token` cookie (HttpOnly, SameSite=Lax,
  `Path=/`, Secure when `COOKIE_SECURE=true`). Scripts cannot read it, so an XSS bug cannot exfiltrate the
  token the way it could from localStorage.
- **CSRF:** a double-submit token is stored in the `csrf_token` cookie. It is sent back in the `X-CSRF-Token`
  header or the `csrf_token` form field and compared in constant time. State-changing web requests must also
  carry an `Origin` header whose host matches the request host. SameSite=Lax adds a further layer of defense.
- **Headers:** web routes send a strict CSP (`script-src 'self'`, no inline scripts or styles),
  `X-Content-Type-Options: nosniff`, and `Referrer-Policy: same-origin`.
- **Templates:** only `html/template` contextual autoescaping is used. There are no trusted types
  (`template.HTML`, `JS`, `URL`, ...) and no `text/template`. `internal/handler/web/audit_test.go` enforces
  this.
- **Passwords:** bcrypt with the default cost. Login failures return a generic `invalid credentials`.
- **Webhook:** an HMAC-SHA256 signature over `timestamp.body`. It is sent asynchronously and never changes
  the HTTP response. The Lambda enforces a 5-minute replay window.

Reviewed findings and their triage are in [`security_audit.md`](./security_audit.md). The design rationale
is in [`security_design.txt`](./security_design.txt) and [`design_v10.txt`](./design_v10.txt).

## Build and isolation

`make build` produces a static binary (`CGO_ENABLED=0`, `-trimpath`) at `bin/movies-api`. Templates and
assets are embedded (`web/templates.go`, `web/static.go`). `make verify-isolation` copies the binary into an
empty temporary directory and requests embedded pages and assets. This proves the binary does not need the
source tree at runtime. PostgreSQL remains the only external runtime dependency.

## Testing

- `go test -race -count=1 ./...` runs the full in-memory suite. It needs no database, and CI runs it.
- `internal/app/stage*_test.go`, `helpers_test.go`, and `variants_test.go` are the official contract tests.
  They are checksummed in `.github/tests.sha256` and select expected behavior from the root `VARIANT` file.
- `make test-integration` runs the PostgreSQL repository tests against an isolated `_test` database.
- CI requires gofmt, `go vet`, and passing tests, then scores them with `scripts/score.py`.

## Known limitations

- Roles are read from JWT claims, so a role change takes effect only after the user's existing token
  expires.
- There is no rate limiting on login or registration.
- Duplicate API registration reveals that an email is already registered (audit finding 8, tracked).
- The Origin check compares hosts only. Deployments behind a TLS-terminating proxy should also validate the
  public scheme and origin.
